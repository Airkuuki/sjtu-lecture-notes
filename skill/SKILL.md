# 交大课堂听课笔记流水线

把课堂录像变成**能直接当复习资料读**的正式笔记。全流程不下载视频（远程 Range 拉流），一讲约 30 MB 磁盘、约 5 分钟机器时间。

## 何时使用

- "把 `某门课程` 第 X 周周二的课整理成笔记"
- "某门课这周讲了什么"
- "扒一下这讲的平台字幕"
- "抓一下这讲的板书和 PPT"
- 补落下的课、批量处理整门课

## 位置与环境

**本 skill 自带一份完整可运行的代码快照**（`scripts/` + `config.toml` + `run.ps1` + `tests/` + `docs/笔记模板.md`），
所以换会话、换工作目录都能直接用。有两种用法，**区别只是"代码从哪跑、大文件放哪"**。

### 方式 A：本机项目目录（推荐）

```
<工作副本>\     ← 代码 + 笔记（进 git）
<data_root>\    ← 一切大文件（音频/帧/合成/依赖）
```

```powershell
$env:PYTHONPATH = '<data_root>\pylibs'
cd '<工作副本>'
python scripts/cli.py status
```

### 方式 B：直接从 skill 目录跑（别的会话 / 别的机器）

```
%USERPROFILE%\.dsh\skills\sjtu-lecture-notes\   ← 本 skill（代码快照，可直接运行）
```

```powershell
$S = "$env:USERPROFILE\.dsh\skills\sjtu-lecture-notes"
$env:PYTHONPATH = '<data_root>\pylibs'

python "$S\scripts\cli.py" status                    # 自检：能跑通
python -m unittest discover -s "$S\tests" -t "$S"     # 自检：86 例测试
```

两种方式读写**同一批笔记**（skill 的 `config.toml` 里 `notes` 指向方式 A 的笔记目录），不会出现两份。

- **磁盘纪律**：代码在 C，数据全在 D。不要往 C 盘写大文件，不要复制 ffmpeg。
- **代码分叉处理**：改完方式 A 的代码后，要把快照同步到 skill 目录再跑
  （本机用 `sync_skill.ps1`，带 `-Check` 只比对不写入；发布仓库里不含这个脚本）。

### 首次在新环境使用

1. **依赖**（requests / imageio-ffmpeg / pydantic / ffmpeg-python）。若 `<data_root>\pylibs` 不存在：
   ```powershell
   python -m pip install --target <data_root>\pylibs -r requirements.txt --no-cache-dir
   ```
   ffmpeg 用 `imageio-ffmpeg` 自带那份，**不要复制它**。
2. **令牌**。二选一：
   - 把 `.env.example` 复制成 `.env`，填入 `CANVAS_API_KEY=<令牌>`；或
   - 设环境变量 `$env:CANVAS_API_KEY = '<令牌>'`（`load_env` 里 `setdefault`，环境变量优先）

凭据**只放 `.env` 或环境变量**，已 gitignore。**不要把令牌写进命令行或输出**。

## 保存位置（必须遵守）

**先看用户有没有明确说放哪，再决定落点。**

| 情况 | 落点 |
|---|---|
| 用户**明确指定**了目录 | 用用户给的目录（`TINGKE_DATA` / `TINGKE_NOTES` 环境变量或 `config.toml`） |
| 用户**没说** | `<工作区>/<课程名>/课程转写/` |

**"切片数据"（音频、帧、合成材料包）与笔记同理，都跟随课程走。**

```
<工作区>/                      ← 当前目录含 听课助手/ 的那层，或项目根的父目录
└── <课程名>/
    └── 课程转写/               ← 转写、帧、合成、笔记全在这里
        ├── 字幕/<节次>/transcript.json
        ├── 帧/<节次>/{board,ppt}/
        ├── 合成/<节次>/material.md
        └── <日期>_<节次>.md     ← 笔记正文
```

判断工作区的顺序：`TINGKE_WORKSPACE` 环境变量 → 当前目录（其下有 `听课助手/`）→ 项目根的父目录。

**不要**把产物写进系统盘根目录或项目源码目录；**也不要**未经询问就换到别处。
用户说"放某某目录"时，改 `config.toml` 的 `paths.data_root` / `paths.notes`，
或用 `TINGKE_DATA` / `TINGKE_NOTES` 临时覆盖，不要改代码。

## 两条线（重要）

| 环节 | 谁做 |
|---|---|
| 认证、转录、抓帧、合成、骨架、体检 | **程序**（幂等、全自动） |
| 写笔记正文 | **你（Agent）** —— 需要理解内容、核对公式、取舍重点 |
| 渲染验证、内容抽查 | **你** —— 子代理的自查不算数，必须自己重验 |

原则：**程序算事实，Agent 组织语言**；凡是能机械验证的一律不靠人眼。

## 完整流程

### 第 1 步（前置）：确认或索取 Canvas API 令牌

**这是唯一需要用户提供的外部输入，不能跳过、不能猜、不能借用别人的令牌。**

先查是否已有令牌（任一即可）：

```powershell
# 方式 A: skill 目录下的 .env
Test-Path "$env:USERPROFILE\.dsh\skills\sjtu-lecture-notes\.env"
# 方式 B: 环境变量
if ($env:CANVAS_API_KEY) { "已有环境变量" }
```

**都没有时，向用户索取**，并给出获取方式：

> 需要你的交大 Canvas **个人访问令牌**（Personal Access Token）：
> 1. 打开 https://oc.sjtu.edu.cn 并登录
> 2. 右上角头像 → **Account（账户）** → **Settings（设置）**
> 3. 页面下方 **+ New Access Token**，填个用途名（如 `tingke`），生成后**复制**那串令牌
> 4. 把它给我

**拿到令牌后的安全写法（三选一，按推荐排序）：**

1. **最稳：让用户自己写**。给出模板，用户填完我们只验证：
   ```powershell
   # 用户自行执行(令牌不经过对话记录)
   Copy-Item "$env:USERPROFILE\.dsh\skills\sjtu-lecture-notes\.env.example" `
             "$env:USERPROFILE\.dsh\skills\sjtu-lecture-notes\.env"
   notepad "$env:USERPROFILE\.dsh\skills\sjtu-lecture-notes\.env"   # 填入 CANVAS_API_KEY=...
   ```
2. **用户在对话里发令牌**：写入 `.env` 时**用不会回显的方式**，不要在回复里复述令牌；
   并**必须提醒**："该令牌已出现在聊天记录中，建议用完去 Canvas 后台吊销、重新生成。"
3. **临时会话**：只设环境变量，不落盘：
   ```powershell
   $env:CANVAS_API_KEY = '<令牌>'    # 仅当前进程有效
   ```

**安全红线（任何时候）：**
- 绝不把令牌打印到输出、日志、报告、提交信息里；
- 绝不写进 git 跟踪的文件（`.env` 已在 `.gitignore`，别改名绕开）；
- 不要把令牌拼进命令行参数（会进命令历史）；用 `.env` 或环境变量；
- 若发现令牌曾被贴进聊天/issue/文档，提醒用户**吊销并重新生成**。

### 第 2 步：认证自检

```powershell
& $py scripts\cli.py auth-check
```

输出"认证链: 通过"才继续。失败会打印认证链走到第几跳，据此判断是权限问题还是平台问题。

### 第 3 步：定位节次

```powershell
& $py scripts\cli.py list-courses                     # 6 门课，含 tecl_id
& $py scripts\cli.py list-lectures --course-id 2001   # 节次：id / 日期 / 可播放 / 有无平台字幕
```

- `playable=false` 的讲平台还没转码，**不能处理**（实测有的课 14 讲只有 4 讲可播放）
- `has_transcript` 表示平台是否已生成 AI 字幕；新讲有约 **1 周延迟**
- 周次换算：以第一周第一次课为基准往后推；平台记录里也有 `weekNo` 字段可核对

### 第 4 步：转录（二选一）

**A. 扒平台字幕**（"官方出品"，但新讲没有）

```powershell
& $py scripts\cli.py subtitles --course-id 2001 --lecture-id 1001
```

- 有则存 `platform.json/.srt/.txt`；无则明确报 `unavailable`（**不会编造**）
- 平台字幕是 15~100 秒整块、无句级时间戳，工具会按句末标点切句 + 按字数比例插值

**B. bcut-asr**（立即可用，有句级时间戳）

```powershell
& $py scripts\cli.py transcribe --course-id 2001 --lecture-id 1001
```

抽音频（约 2 分钟）+ 识别（约 30 秒），产出 `transcript.json/.srt/.txt`。

**C. 两者都要/新讲没有平台字幕时**：额外抓**平台 PPT 切片 OCR**，它是官方 OCR，**术语比语音识别准得多**，用来校正 ASR 的术语错误：

```powershell
# 通过脚本调用平台接口（GET /v1/course/ai/ppt?courseId=<节次id>）
# 返回 docList[].ocrText / imageSeekTime(秒) / textKeywordList
# 落到 <data_root>\字幕\<课程>\<节次id>\ppt_ocr.txt
```

### 第 5 步：抓两路帧（并行，约 4~5 分钟）

```powershell
& $py scripts\cli.py frames --course-id 2001 --lecture-id 1001
```

- **通道 0 = 教室摄像头**（黑板手写）：定时采样 30s + JPEG dHash 去重
- **通道 1 = 屏幕录屏**（PPT）：15s 采样 + **相邻采样点** dHash 去重
- `--mode board|ppt|both` 可只抓一路

### 第 6 步：合成材料包

```powershell
& $py scripts\cli.py merge --course-id 2001 --lecture-id 1001
```

产出：
- `material.md` —— 单文件材料包：元信息 + 全程字幕（带 [mm:ss]）+ 帧索引 + 帧目录绝对路径
- `timeline.md` —— 三路对齐表

**写笔记前先读 `material.md`。**

### 第 7 步：生成骨架 + 刷新索引

```powershell
& $py scripts\cli.py notes --course-id 2001 --lecture-id 1001
```

骨架**绝不覆盖已写好的笔记**。同时刷新课程索引 `04_产出/04_笔记/<课程>/_index.md`。

### 第 8 步：写正文（核心工作）

读 `material.md` + `transcript.txt` + `ppt_ocr.txt`，
**遇到公式推导、图表、题干这类字幕不可靠的地方，直接看板书帧/PPT 帧核对**，然后按下面的格式写。

写到 `04_产出/04_笔记/<课程>/<日期>_<节次id>.md`。

### 第 9 步：交付前体检（不过不交付）

```powershell
& $py scripts\cli.py check-note --path '04_产出\04_笔记\某门课程\20260101_1001.md'
```

必须显示 `笔记体检: 通过`。检查项见下节。

## 笔记格式（硬规则）

1. **严格按讲课时间顺序组织**：章节顺序 = 老师讲的顺序，不按知识点重新归类。
2. **全文不出现时间戳**（`[mm:ss]` 一律不写），**不做时间轴附录**、**不做识别修正记录附录**。
3. **只写重点**：定义、定理、公式、例题、老师的强调与提醒。
   **闲聊（排课吐槽、天气、食堂）与课后杂音一律不写。**
4. **可以引用老师原话**，用引用块：`> 老师说：「…」`。
   **原话必须逐字来自字幕**，不许润色成意思相近的另一句。
5. **书面语（讲义体）**：用"设 / 由…可得 / 代入得 / 从而 / 即 / 此处易出错"；
   不用"怎么、为啥、搞定、坑、就得把…加起来"。
6. **必须写「引入过程」与「推导过程」**（最容易偷懒、最影响复习价值）：
   - **引入**：从哪个旧知识出发 → 提出什么问题 → 为什么这样定义。
   - **推导**：每个公式/性质/关系式都要给出**推导或证明**，中间结果要出来。
     性质要给证明；关系式要写求导/积分步骤并标明所用定理；型公式要严格推导，仅有直观不算完成。
   - **老师只给直观、未给证明时，必须补出证明并标注"此处为笔记补充"**。
   - 只给结论的笔记等于抄书 —— 视为未完成。
7. **不确定就说不确定**：听不清写"（听不清）"，不要补全成通顺但错误的内容。
8. **附录只保留「板书帧速览」一个，且必须直接嵌原图**（不是帧号表格）：

```markdown
## 附录：板书帧速览

**板书 0043**（21:00）一维与二维对照，及例题完整推导

![](帧/<节次>/board/frames/f_00043.jpg)
```

   **图片必须用相对路径**（相对笔记所在目录），三条理由：

   - 绝对路径（`C:/Users/...`、`D:/...`）换机器/换落点就断，网页预览也解析不了；
   - Windows 绝对路径常含空格（如 `work station`），CommonMark 的 destination
     不允许裸空格，整行会退化成普通文字 —— 连语法都过不了；
   - 相对路径能跟着「课程转写」整门课一起打包/搬走，Typora / VSCode 预览正常。

   所以**帧数据要和笔记放在同一门课的 `课程转写/` 下**（`帧/<节次>/...`）。
   `check-note` 会校验相对路径能否解析到真实文件，并拒绝绝对路径、拒绝裸空格。

### LaTeX 三大约束（违反会渲染报错）

| 约束 | 原因 |
|---|---|
| 块级公式必须**单行** `$$...$$` | 跨行块会让渲染器在第一行之后原样输出，后续 markdown 全部失效 |
| 块级公式必须**顶格** | 缩进会被当成列表项延续或代码块 |
| 数学片段里**不得出现 `\|`** | 表格先按 `\|` 切单元格，会切出落单 `$`；要用 `\mid` |
| 数学片段里不得有中文/全角 | 各渲染器表现不一致 |

## 常见坑（全部实测踩过）

### 1. 帧号 ≠ 文件名
`index.json` 的 `id` 是 4 位（`0149`），文件名是 5 位（`f_00149.jpg`）。
**定位帧一律用条目的 `path` 字段**。用 id 拼路径会读不到文件（会误报"帧全部缺失"）。
且 `id` 是原始采样序号、去重后**不连续**。

### 2. 平台字幕对新讲有延迟
实测第 7 周的讲 `transcriptOptimizeTaskStatus=0`、接口返回 `null`；第 6 周及更早已就绪。
所以新讲要么等一周，要么用 bcut-asr + PPT OCR 组合。

### 3. 抓帧算法的演进（不要退回去）
| 尝试 | 结果 |
|---|---|
| `select='gt(scene,0.12)'` 场景检测 | **失败**：scene 比较 25fps 相邻帧，PPT 切换动画被摊薄，55 分钟只检出 2 处 |
| 一条流里按 1fps 算 dHash | **失败**：判出 31 个"变化点"，按 JPEG 复核只有 5 个真实画面 |
| **定时采样 + 对 JPEG 算 dHash** | **有效**：板书 110→78 帧、PPT 219→14 帧 |

关键细节：静态画面（PPT）必须用 `compare="previous"`（相邻采样点比较 = 边沿检测），
因为与"上一保留帧"比较时，静态段每采样点 1 bit 的噪声会累积成假变化；
摄像头画面（一直在动）才用 `compare="last_kept"`。两者都在 `config.toml` 里。

### 4. 板书可能只覆盖前半讲
有的老师讲完推导就擦黑板只留提纲，后半段公式全在投影上。
这时要**用 PPT 帧读公式**，并在附录里补足对应 PPT 帧图。

### 5. ASR 的术语错误是系统性的
数学课常见："拉丝量"→拉格朗日量、"年号"→二维、"适量函数"→似然函数、
"接比C/阶"→J、"二"→r、"伊普斯隆"→ε、"阶差二"→J×r、"波特来病"→Bertrand、
"尼亚可勒夫"→Lyapunov、"量体问题"→二体问题。
**以 PPT OCR 和板书帧为准校正。**

### 6. 一讲里常夹着无关内容
开场签到、招生宣讲、排课吐槽、课间与课后杂音 —— 一律不写进正文，
可在心里跳过；若答疑里有实质内容（如诺特定理、SO(4)），可折入正文并标注来源。

## 分发子代理（并行处理多讲）

一次要处理 **≥2 讲**，或单讲篇幅很大时，把"写正文"分发出去并行做。
**预处理也由子代理各自跑，Lead 只负责验收。**

### 什么时候拆

- 一次 ≥2 讲：**一讲一个子代理**，并行起（一次消息里全部 `subagent`）
- 单讲极长（>40 分钟 / 字幕 >300 句）：也可以按讲拆，比按内容拆干净

### 怎么拆（写作用域必须互不重叠）

- 一个子代理 = 一讲 = 一个笔记文件 `04_产出/04_笔记/<课程>/<日期>_<节次>.md`
- 每个子代理只碰自己那一讲的目录：
  `<data_root>\字幕\<课程>\<节次>\`、`帧\<课程>\<节次>\`、`合成\<课程>\<节次>\`
- **课程索引 `_index.md` 不要在子代理里并发写** —— 由 Lead 最后统一跑一次 `notes` 刷新
- 同时并行 2~3 个为宜：每个子代理的 `frames` 会开两路 ffmpeg，太多会互相抢带宽

### 子代理 prompt 必须写全（缺一项它就会跑偏）

1. **项目位置与环境**：`PYTHONPATH`、python 解释器路径、工作目录
2. **本讲的 course-id / lecture-id**
3. **按顺序要跑的命令**：`frames` → `merge` → `notes`（幂等，已完成的会跳过）
4. **必读材料**：本 skill 的 `SKILL.md`、`docs/笔记模板.md`、**一份已定稿的样板笔记**
5. **材料路径**：`transcript.txt`、`ppt_ocr.txt`（若有）、`合成/.../material.md`
6. **写作硬规则**照抄关键几条：时间顺序、无时间戳、书面语、引入+推导、老师原话、单行 LaTeX、附录嵌原图
